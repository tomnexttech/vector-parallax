# 横向きの iPhone：見出しが一画面に 3〜4 本・札が行を食わない・全画面の地図の二度たたき（v48）

報告（2026-11-09）：v47 のあとも、iPhone の横画面のホームは見出しが 1 本しか読めず、ニュースの画面では見出しの下の札が崩れて行を食う。iPad 縦で、小さい地図を押して開いた全画面の地図は二度たたきで拡大しない（測定で倍率 0）。

## 1. ホームの「空き」は何だったか

自動で流れる一覧の途中を撮った空きではなく、**本当の高さ**だった。横向きの iPhone（`orientation: landscape` かつ高さ 500px 以下かつ幅 1100px 以下）には、一覧の行の小さな写真（`.rth`）の規則が無かった。
写真の規則（84px・4:3・横に並べる）は縦向きのホームの塊（`@media not all and (orientation: landscape) …`）の中にだけあり、横向きでは `.rth` が素の `<img>` になって枠いっぱい（幅 762px・高さ 429px）に出ていた。
一行が 500px で、画面に見える一覧の高さは 221px（844×390）。見出しは写真の下なので、**一覧の先頭でも見出しは 1 本も見えない**。見本の「空き」は前の行の写真の下端（読み込み前の暗い地）、その下に出た 1 本が次の行の見出しだった。

667×375 では更に、横向きの幅の規則（`max-width: 760px`）が最新の出来事の枠 `#p-case` と一覧 `#p-pri` を左の列に縦に積み、右 2/3 が空だった（一覧の高さ 76px）。

## 2. ニュースの札が縦に崩れる

`.rk` は二つの物の名前だった：注目度ランキングの 2 列（`div.rk`、`repeat(auto-fit, minmax(340px, 1fr))` の格子 + 上余白 12px）と、**行の見出しの下の論点の札**（`span.rk`）。
後者にも前者の格子が当たり、札が 340px の列・上余白 12px の箱になって、行の下の段に落ちるか、横に並んだ札の線より 12px 下がって行を 20px→32px にしていた（667×375 では「説明責任」が三段目に落ちて一行 96px）。
`div.rk` に限った。縦向き・デスクトップの行にも同じ余白が付いていたので、そこも揃う。

## 3. 直し（css/app.css の末尾、`/* ---- v48`）

* ホーム（横向き）：最新の出来事の枠は出さず（行を押すと出る）、一覧を行 6 の全幅に置いた。見出しの帯（44px）に「注目ニュース・件数・拡大」と分野の札を一行で並べ（分野の札は横に流れる）、その下が一覧。
* 行：写真 64×48（contain・暗い地）を左、見出し（16px・22px 行・2 行まで）とその下の一行（13px・1 行）を右。一行 54〜59px（見出しが 2 行なら 78px）。上の帯の下の件数の帯は全幅にした（右の黒い空きをやめた）。
* ニュース（横向き）：行を同じ形にし、上の三段（タブ・分野の札・論点の札）を各 44px（見た目はもっと小さく、押せる範囲は疑似要素で 44px）、段の間の余白を 0 にした。論点の札は 13px。
* 文字：一覧・札・件数の帯は 13px 以上（測定で 13px 未満の要素 0）。

## 5. iPad 縦・全画面の地図の二度たたき

原因：**開いた全画面の地図が、ホームの他の枠の下に隠れていた**。`:root[data-mapfull] #p-map` は `position: fixed; z-index: 80` のつもりだったが、枠（`.pane`）はどれも `position: relative; z-index: 1` で、
特異度の高い規則に負けて `#p-map` の `z-index` も実測で **1** のままだった。同じ z-index 1 では後ろに書かれた枠が前に出る。`#p-map` は本文の中ほどなので、iPad 縦（枠が二列に並ぶ幅）では
後ろの枠（注目度ランキング・片側だけのニュース・災害・政治・市場・映像）が地図の上に描かれ、指も枠が受けた（押した所の最前面は `SPAN.rt`・`SPAN.qp`・`SPAN.tyv`・`LI`）。
地図が見えるのは枠の隙間だけで、二度たたきは隙間の地図の上でだけ効く。中央の隙間に当たる押し方では効き、枠の上では 0（測定の倍率 0）。iPhone 縦も同じ並びで、`tools/map_touch_check.mjs` では地図が取れず（0 件）だった。

直し：`:root[data-mapfull] #p-map { … z-index: 80 !important; }`（1 語）。開いた地図は枠の上、画面いっぱい（818×1164）で、どこをたたいても地図が受ける。
測定（`tools/map_touch_check.mjs`・Chrome の端末の真似・タッチ・UA）：

| 場面 | 前 | 後 |
|---|---|---|
| iPad 縦 820×1180・小さい地図を押して開いた地図・二度たたき | 0 | +1.00 |
| iPhone 縦 390×844・同 | 地図が取れず（枠が上） | +1.00 |
| iPad／iPhone・地図の画面（`#map`） | +1.00 | +1.00 |

撮影：`50_design/v8_mobile/before_map_full_820x1180.png`（隠れた地図）と `after_map_full_820x1180.png`。
測り方の注意：描画中（開いた直後でソフトウェア描画の Chrome）に押すと、押している時間が MapLibre の 500ms を越えて 0 になることがある。ツールは地図が止まる（`loaded() && !isMoving()`）のを待ってから押す。
押す所は中央を外す（中央は出来事の印で、押すと札が開く＝押しであって拡大ではない）。

## 6. 残った物

* 上の帯（横向き 36px）に 44px のボタン（AI／自動、表示）が入り、下端が切れる（v47 から）。帯を 44px にすると一覧が 8px 減って 667×375 のニュースの見出しが 3→2 本になるので、そのままにした。
* ボードの画面（`#home` から「ボード」）の `nav.jump` は横に流れる帯のまま（v47 の頁一覧に無い。HEAD の CSS でも同じ）。
* 一覧の行の中の小さな札（分野・社数・論点）は 20px の高さのまま（行そのものが 54px 以上の押せる所）。
